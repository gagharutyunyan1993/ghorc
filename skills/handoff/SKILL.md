# Самопередача лида (версия 1: skill, без скриптов и локов)

Пути и параметры - из `.claude/ghorc.json`: `lead.model`, `lead.effort`, `thresholds.*`, `handoff.statePath`, `handoff.handoffPath`, `handoff.allowSendKeysExit`, `handoff.candidatePermissionArgs`.

## Постоянное разрешение владельца
Заполняется один раз в конфиге проекта, здесь только читается:
- `handoff.allowSendKeysExit` = `true`: новый лид может послать `/exit` в старую вкладку через `herdr agent send-keys`. При `false` (по умолчанию) `/exit` старой вкладке отправляет владелец.
- `handoff.candidatePermissionArgs`: аргументы режима прав кандидата (как у старого лида). Пусто - кандидат стартует с правами по умолчанию, скажи об этом владельцу.
- Новый лид закрывает старую вкладку только по слову владельца, записанному в конфиге или STATE.

## Предусловия
- `HERDR_ENV=1` (лид работает внутри herdr). Иначе - запасной путь ниже.
- Ноль фоновых агентов и фоновых команд лида (иначе уведомление разбудит старого лида после STOP). herdr-воркеры перечислены в HANDOFF (pane id).
- Новые сообщения владельца во время передачи записать в STATE до запуска кандидата.

## Триггеры
- Контекст ≥ `thresholds.ctxHandoff` (150K) на границе пакета: передача. ~170K - на ближайшей границе этапа. Контекст - из `node "${CLAUDE_PLUGIN_ROOT}/scripts/ctx.cjs"`.
- С `thresholds.ctxPrepare` (120K): обновить STATE на границе этапа.
- Новый контекст кандидата сразу велик - диагностируй стартовые инструкции, а не ротируй снова.

## Шаблон HANDOFF (≤50 строк; `templates/HANDOFF.md`)
Заполни файл по `handoff.handoffPath`: handoff_id, status (DRAFT), old_session_id, причина; цепочка пакетов и стадии; фоновые процессы; решения смены; незакрытые сообщения и обещанные действия; первые 3 шага.

## Команды herdr (без `--wait`)
```
herdr tab create
GHORC_ROLE=lead herdr agent start lead-next --kind claude -- --model <lead.model> --effort <lead.effort> <handoff.candidatePermissionArgs>
herdr agent prompt lead-next "Прочитай <путь HANDOFF>. Сверь с git и статусом проекта. Ответь строго: READY handoff=<id>; Следующее действие: <одно>; Несоответствия: <нет/список>. Ничего не меняй, пока старый лид не завершится. Свою ротацию не начинай."
herdr agent wait lead-next --until idle,blocked   # тайм-аут 10 минут
herdr agent read lead-next
```
`herdr agent prompt --wait` не использовать (риск повторной отправки хуком).
Кандидат-лид стартует с `GHORC_ROLE=lead` (PowerShell: `$env:GHORC_ROLE='lead'; herdr agent start ...`); любой другой herdr-воркер - с `GHORC_ROLE=worker` (`$env:GHORC_ROLE='worker'`), чтобы не получить напоминание лида. Наследование переменной herdr-ом не проверено живьём: проверь в первой сессии строку SessionStart.

## Протокол READY / STOP
Ответ кандидата:
```
READY handoff=<id>
Состояние прочитано: <путь>
Следующее действие: <одно конкретное действие>
Ограничения: <merge/release/оплата>
Несоответствия: <нет / список>
```
1. Старый лид читает READY; при несоответствиях исправляет HANDOFF и повторяет в той же вкладке.
2. Кандидат `blocked` или тайм-аут READY (10 минут): старый закрывает кандидата (`/exit` в его вкладку, закрывает созданную вкладку), `handoff_id` гасится, старый продолжает работу.
3. READY принят: старый пишет в файл `status: SENT`, печатает `HANDOFF SENT - STOP` и больше ничего не делает. `/exit` он выполнить сам не может (это пользовательский ввод): его шлёт новый лид через `herdr agent send-keys` (если `allowSendKeysExit`) или владелец.
4. Новый лид начинает только когда `herdr agent get` показывает завершение старого; последнее сообщение владельца в старой вкладке читает через `herdr agent read`.
5. READY - отчёт, не доказательство: SHA, ветку, процессы новый лид проверяет сам командами.

## Защита
- Один кандидат на `handoff_id`; повтор команды возвращает состояние существующей передачи.
- После 2 неудачных передач - стоп и вопрос владельцу.
- Кандидат не запускает свою ротацию до активации (до завершения старого лида).
- Dirty-изменения не удалять ради «чистого приёма»; процессы по имени `claude` не убивать.

## Запасной путь (herdr недоступен)
Обнови STATE, владелец делает `/clear`, затем «прочитай STATE». Дешевле, но память процесса не освобождает.
