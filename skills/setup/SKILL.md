# ghorc setup

1. Run `node "${CLAUDE_PLUGIN_ROOT}/scripts/setup.cjs" --check` (add `--cwd <project>` if the session is not in the project). It prints one line per item and a final JSON line.
2. Show the user a table: item, current value, recommended value, why. Mark items that are already `ok`.
3. Ask which missing items to apply. Apply only what the user confirms:
   `node "${CLAUDE_PLUGIN_ROOT}/scripts/setup.cjs" --apply statusLine,pct,idle,config,claudemd,exclude`
   `pct` is GLOBAL (all projects); offer `--project` (writes `<project>/.claude/settings.local.json`) when the user wants it for this project only. `--apply all` skips warnings; use it only if the user said "apply everything", including model and effort.
4. `model` and `effort` are owner-level decisions (global model and effort of every session): never include them without an explicit yes for exactly those two items. The same holds for cache TTL, which this script does not touch.
   **Permission mode** (item `permissions`, WARN until chosen): ask the owner every time it is not `ok`, with `AskUserQuestion` and these three options, and never pick one yourself:
   - `bypass`: tab workers and candidate leads start with `--permission-mode bypassPermissions` and never wait on a permission prompt; ghorc's hooks and the owner's deny rules still deny, critical-path removals and `AskUserQuestion` still stop them. Offer `bypassPrompt` right after (it pre-accepts the one-time bypass warning globally, so the first tab does not stop on it).
   - `acceptEdits`: edits pass without a prompt, other tools still ask; a tab may stop on a shell command.
   - `prompts`: default permissions (`[]`); every tool asks and an unattended tab stops until someone answers in it.
   Then run `--apply permissions --mode <answer>` (with `bypass` and a yes to the warning key: `--apply permissions,bypassPrompt --mode bypass`). It writes both `worker.permissionArgs` and `handoff.candidatePermissionArgs`; `--apply all` never does.
5. `--apply` backs up `~/.claude/settings.json` to `settings.json.ghorc-<timestamp>.bak`, changes only the listed keys and prints a diff. Show the diff to the user. Settings changes take effect in a new session.
6. Run `--check` again and report the result; the status line, autocompact and model changes need a restart of the session.

Items: `statusLine` (ghorc status line), `statusLineStale` (statusLine points to an older plugin version; same fix), `pct` (`env.CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` = `ctxHandoff` + 35K as a share of the window, rounded up: 30 for a 1M window; a value that compacts at or below `ctxHandoff` is wrong), `idle` (`idleCompaction` = false), `model` (config `lead.model`), `effort` (config `lead.effort`), `bypassPrompt` (warning item and owner decision, never part of `--apply all`; name it only after the owner says yes: `skipDangerousModePermissionPrompt` = true in the user settings, needed only when the owner chose `--mode bypass`: the first bypass start would stop on a one-time warning dialog), `permissions` (warning item and owner decision: the permission mode of tab workers and candidate leads; ask, then `--apply permissions --mode <bypass|acceptEdits|prompts>`), `config` (`.claude/ghorc.json` from the template), `claudemd` (the `<!-- ghorc -->` section in `CLAUDE.md`), `exclude` (`.claude/ctx-*.json`, `.claude/ctx-*.tmp` and `.claude/ghorc-out/` in git `info/exclude`), `heavy` (warning item: `heavyCommands` empty or no match for `checks.full`; `--check` prints a proposed regex list from the `package.json` scripts of the root and `app/`; show it to the user and, only after a yes, run `--apply heavy`, which prints the list and writes it to the project config), `watchdog` (opt-in: `watchdog.autostart` is false by default; `--apply watchdog` sets it true in the project config; stop a running one with `node "${CLAUDE_PLUGIN_ROOT}/scripts/watchdog.cjs" --stop`). `explore` (opt-in: writes `<project>/.claude/agents/Explore.md` on `haiku` from the template, because the built-in Explore runs on the session's model, Opus for a ghorc lead; an existing file is never overwritten; offer it with its why-line). `heavy`, `watchdog`, `explore` and `bypassPrompt` are never part of `--apply all`: name them.

Opt-in guards (each is a WARN item, off by default, never part of `--apply all`; `--apply <item>` sets only its key in `.claude/ghorc.json`): offer EACH one to the owner with its why-line from `--check`, and apply only on a yes. `capacity` (`capacity.enabled`: demands an idle reason when the machine has spare capacity, watches the weekly cap), `heavySlots` (`heavySlots.slots` = 2: limits heavy checks per machine; the check command must go through `scripts/heavy-slot.cjs`), `pushGuard` (`handoff.pushGuard`: no candidate lead while in-flight branches are unpushed), `stickyOnCompact` (`handoff.stickyOnCompact`: a compaction makes the lead hand over at once, because the token number is wrong after it; it binds a session with `GHORC_ROLE=lead` and a roleless session whose terminal proves it is the lead (hc: terminal named with `capacity.leadNamePrefix` or without a parent; herdr: tab label starting with the prefix); `GHORC_ROLE=worker` is never bound, so offer it when leads run with `GHORC_ROLE=lead` or in tabs named with the prefix). `--check` also prints an info line on `handoff.candidatePermissionArgs` (set or not); it can bypass permission prompts, setup never writes it and does not offer it.
